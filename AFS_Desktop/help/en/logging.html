Log and notification

Edit → Logging settings… controls what is written down and how you learn about serious errors.

Log

Log file path Location of the log file. Without a path of your own, AutoFileSync writes to %LOCALAPPDATA%\autofilesync\autofilesync.log on Windows and to ~/.cache/autofilesync/autofilesync.log on Linux. The directory is created when needed.
Log level From which level on entries are written: Debug, Info, Warning, Error or FatalError. Debug logs every step and makes the file grow fast – meant for tracking down problems, not for continuous operation. Info records what was copied and deleted.
History [days] How long entries are kept. At program start older lines are removed, newer ones stay.
Editor Program with which View → Show log file opens the log.
Path for backup proofs Directory for the proof files, see Backup proof.

Notification by e-mail

On the second tab you can set up a notification that sends an e-mail on a serious error – useful when AutoFileSync runs unattended or as the background service.

Active Switches sending on. Without the tick everything else has no effect.
E-mail address Recipient of the notification.
Outgoing mail server, Port SMTP server and port of the provider.
User, Password Login data for the outgoing mail server.
Sender Address entered as the sender. Many providers require it to belong to the account.

If recipient, server or sender are missing while the notification is active, the dialog points this out when you confirm it. The same error does not send a mail any number of times – after one message it stays quiet for a while, so that a target that cannot be reached for a long time does not flood the mailbox.
