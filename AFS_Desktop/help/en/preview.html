Preview

Synchronisation → Preview… shows what a run would do now without changing anything: nothing is copied, moved or deleted. Only when you choose Synchronise now in the dialog does the synchronisation run – exactly as if you had chosen Synchronise once.

The preview pays off above all

  • after creating a new synchronisation, to check that source and target are the right way round,
  • before you switch on Delete files in the target that were deleted or Delete source after copying for the first time,
  • when you want to know how much a run would transfer.

The dialog

Each row is a step the run would carry out:

ActionMeaning
Copy to target The file is new or newer in the source than in the target.
Move to target Like copying; afterwards the source file is removed because Delete source after copying is set.
Copy back to source With two-way synchronisation: the file exists only in the target or is newer there.
Delete in target The file no longer exists in the source and Delete files in the target that were deleted is set. These rows are red because they are the only ones that remove data.

Below the list is the summary: how many steps, how many of them deletions and how much data would be transferred. Messages of the check – an unreachable source, for instance – appear below the list. If a great many steps are planned, the list shows the first ten thousand and names the number of the rest.

If source and target match, only a note that a run would do nothing appears instead of the dialog.

What the preview does not take into account

  • The pause of a synchronisation plays no part: the preview shows the difference between source and target, even right after a run.
  • Whatever changes between the preview and the run is only seen by the run.
  • Errors during the copy itself – a full target, say – only show up during the run and are then in the log.
