Protokoll und Benachrichtigung

Bearbeiten → Logging-Einstellungen steuert, was mitgeschrieben wird und wie Sie von schweren Fehlern erfahren.

Protokoll

Protokolldatei-Pfad Ort der Protokolldatei. Ohne eigene Angabe schreibt AutoFileSync unter Windows nach %LOCALAPPDATA%\autofilesync\autofilesync.log, unter Linux nach ~/.cache/autofilesync/autofilesync.log. Das Verzeichnis wird bei Bedarf angelegt.
Log Level Ab welcher Stufe geschrieben wird: Debug, Info, Warning, Error oder FatalError. Debug protokolliert jeden Schritt und lässt die Datei schnell wachsen – für die Fehlersuche gedacht, nicht für den Dauerbetrieb. Info hält fest, was kopiert und gelöscht wurde.
Historie [Tage] Wie lange Einträge aufbewahrt werden. Beim Programmstart werden ältere Zeilen entfernt, jüngere bleiben stehen.
Editor Programm, mit dem Ansicht → Log-Datei anzeigen das Protokoll öffnet.
Pfad für Sicherungsnachweise Verzeichnis für die Nachweisdateien, siehe Sicherungsnachweis.

Benachrichtigung per E-Mail

Auf dem zweiten Reiter lässt sich eine Benachrichtigung einrichten, die bei einem schweren Fehler eine E-Mail verschickt – nützlich, wenn AutoFileSync unbeaufsichtigt oder als Hintergrunddienst läuft.

Aktiv Schaltet den Versand ein. Ohne Häkchen bleibt alles andere wirkungslos.
E-Mail-Adresse Empfänger der Benachrichtigung.
Postausgangsserver, Port SMTP-Server und Port des Anbieters.
Benutzer, Passwort Zugangsdaten für den Postausgangsserver.
Absender Adresse, die als Absender eingetragen wird. Viele Anbieter verlangen, dass sie zum Konto gehört.

Fehlen bei aktiver Benachrichtigung Empfänger, Server oder Absender, weist der Dialog beim Übernehmen darauf hin. Derselbe Fehler löst nicht beliebig oft eine Mail aus – nach einer Meldung bleibt er für eine Weile stumm, damit ein dauerhaft nicht erreichbares Ziel nicht das Postfach flutet.
