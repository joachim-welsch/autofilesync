Якщо щось відбувається не так, як очікувалося

Насамперед завжди дивіться журнал. На рівні Info у ньому записано, що скопійовано й видалено; на рівні Debug – також, який файл пропущено і з якої причини.

Файл не копіюється

  • Він порожній. Файли розміром 0 пропускаються, поки не ввімкнено Синхронізувати порожні файли. Журнал зазначає «Порожній файл джерела не скопійовано».
  • Шаблон не підходить або діє виняток, див. Створення синхронізацій.
  • Призначення новіше за джерело. Без Копіювати, навіть якщо файл призначення новіший воно залишається недоторканим.
  • Джерело і призначення вважаються однаковими. Якщо файли порівнюються лише Часом, зміна вмісту без нового часу зміни залишається непоміченою. У такому разі додатково ввімкніть Розмір або Вмістом.
  • Синхронізація не активна – немає позначки Синхронізація активна.
  • Ідеться про вкладену папку, а синхронізація має тип Папка. Для вкладених папок потрібен тип Дерево папок.

Файли копіюються під час кожного запуску, хоча вони не змінювалися

Призначення зберігає час зміни грубіше, ніж джерело, наприклад диск NTFS або FAT як призначення для диска Linux. Копія тоді на частки секунди випереджає оригінал, і при порівнянні Часом джерело вважається новішим. Це враховує Допуск у секундах на вкладці «Параметри»; він дорівнює 0, якщо хтось його вимкнув. Зсув рівно на одну годину на всіх файлах вказує на FAT після переходу на літній чи зимовий час, див. там само.

У призначенні нічого не видаляється, хоча параметр увімкнено

  • Джерело недоступне. Від'єднаний диск, непід'єднана мережева папка або недоступний сервер SSH призводять до того, що не видаляється нічого. Так задумано.
  • Тип – «Файл». Параметр діє лише для типів «Папка» і «Дерево папок».
  • Шаблон або виняток виключають файл із синхронізації – тоді він і не видаляється.
  • Ідеться про папку. Віддзеркалюються файли; папка, видалена в джерелі, залишається в призначенні.

Синхронізація взагалі не відбувається

  • Чи працює фонова служба? Служба і програма не синхронізують одночасно.
  • Якщо Запустити і Синхронізувати один раз неактивні, конфігурація не містить синхронізації, яку можна виконати, – наприклад, тому що всі неактивні або бракує джерела й призначення.
  • Чи було збережено конфігурацію після останньої зміни?
  • Для джерела чи призначення через SSH: чи відповідає протилежна сторона? AutoFileSync перевіряє це перед кожним запуском і пропускає синхронізацію, поки сервер недоступний або вхід не вдається. У журналі тоді стоїть «Шлях SSH недоступний» разом із причиною.
  • Сервер знову доступний, але нічого не відбувається. Результат перевірки доступності кешується, щоб не кожен запуск встановлював нове з'єднання. Після невдалої спроби повторна перевірка відбувається щонайменше через кілька секунд, а при тривалому збої – не частіше ніж раз на п'ять хвилин. Тож може минути до п'яти хвилин, поки відновлене з'єднання буде помічене.

З'єднання SSH не вдається

  • Помилка автентифікації – ім'я користувача або пароль неправильні, або сервер не дозволяє вхід за паролем.
  • Помилка з'єднання – хост або порт недоступні.
  • Ключ хоста змінився – сервер представляється іншим ключем, ніж уперше. Тоді AutoFileSync перериває з'єднання. Якщо зміну можна пояснити, наприклад після перевстановлення сервера, старий запис треба видалити з файлу known_hosts у вашому профілі користувача.
  • Обліковий запис SSH не знайдено – назва перед двокрапкою у шляху не належить жодному створеному з'єднанню. Так буває, наприклад, коли з'єднання перейменовано; відповідні синхронізації тоді все ще вказують на стару назву.

У всіх цих випадках відповідну синхронізацію для цього запуску пропускають: нічого не копіюється і не видаляється. Решта синхронізацій працює як звичайно.

Повернення видалених файлів

Якщо режим видалення встановлено на Перемістити до кошика, файли лежать у вказаній там папці кошика, зі структурою місця, звідки вони походять. При Видалити остаточно і для призначень через SSH такої копії немає.

Якщо файл призначення було перезаписано, допоможе Принцип поколінь – за умови, що його було ввімкнено заздалегідь: попередня версія тоді лежить поруч із файлом як .bak.1.
