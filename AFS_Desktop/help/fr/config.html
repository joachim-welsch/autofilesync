Fichier de configuration

Toutes les synchronisations, connexions SSH et tous les paramètres se trouvent dans un fichier au format JSON. C'est ce fichier que se partagent le programme et le service en arrière-plan.

Où il se trouve

Windows %APPDATA%\autofilesync\autofilesync.json
Linux $XDG_CONFIG_HOME/autofilesync/autofilesync.json, à défaut ~/.config/autofilesync/autofilesync.json
macOS ~/Library/Application Support/autofilesync/autofilesync.json

Ouvrir et enregistrer

  • Fichier → Ouvrir… charge une autre configuration, par exemple un ensemble de synchronisations pour un usage précis.
  • Chaque modification est enregistrée aussitôt – une case cochée dans le tableau comme une boîte de dialogue quittée avec OK. Une étape d'enregistrement séparée n'est pas nécessaire.
  • Fichier → Enregistrer n'est disponible que si l'écriture automatique a échoué, par exemple sur un disque plein. Pendant ce temps, le titre de la fenêtre affiche (non enregistré), et le programme pose la question avant de quitter et avant de démarrer le service en arrière-plan.
  • Fichier → Enregistrer sous… crée une copie. Si le fichier existe déjà, une confirmation est demandée avant de l'écraser.

Ce qu'il contient

Pour chaque synchronisation : nom, type, source, cible, caractère générique, exclusions, options et pause ; en plus les connexions SSH et les paramètres généraux. Les mots de passe des connexions SSH et du serveur de courrier sortant sont enregistrés chiffrés, pas en clair.

Le fichier est en UTF-8 et peut, en cas d'urgence, être consulté avec un éditeur de texte. Une clé qu'une ancienne version du programme ne connaissait pas encore manque tout simplement dans les anciens fichiers – AutoFileSync utilise alors la valeur par défaut documentée et charge le fichier malgré tout. Une seule entrée endommagée ne fait pas non plus perdre toute la configuration ; elle est ignorée.

Lors de l'écriture, le fichier existant n'est pas détruit si l'enregistrement échoue – en cas de doute, l'ancien état est conservé.
