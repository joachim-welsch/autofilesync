Quando qualcosa non va come previsto

Il primo posto da guardare è sempre il log. Al livello Info riporta che cosa è stato copiato ed eliminato; a Debug anche quale file è stato saltato e perché.

Un file non viene copiato

  • È vuoto. I file di dimensione 0 vengono saltati finché Sincronizza file vuoti non è attivata. Il log riporta «Il file di origine vuoto non è stato copiato».
  • Il carattere jolly non corrisponde oppure si applica un'esclusione, vedere Creare sincronizzazioni.
  • La destinazione è più recente dell'origine. Senza Copia anche se il file di destinazione è più recente resta intatta.
  • Origine e destinazione risultano uguali. Se si confronta solo per Data, una modifica del contenuto senza una nuova data di modifica non viene notata. In tal caso attivare anche Dimensione o Contenuto.
  • La sincronizzazione non è attiva – manca la spunta Sincronizzazione attiva.
  • Si tratta di una sottocartella, ma la sincronizzazione è di tipo Cartella. Per le sottocartelle serve il tipo Albero di cartelle.

I file vengono copiati di nuovo a ogni esecuzione anche se non sono cambiati

La destinazione memorizza la data di modifica in modo meno preciso dell'origine, per esempio un disco NTFS o FAT come destinazione di un disco Linux. La copia risulta allora in anticipo di una frazione di secondo rispetto all'originale e nel confronto per Data l'origine conta come più recente. La Tolleranza in secondi nella scheda Opzioni lo compensa; è a 0 se qualcuno l'ha disattivata. Uno spostamento di esattamente un'ora su tutti i file indica FAT dopo il cambio dell'ora, vedere lì.

Nella destinazione non viene eliminato nulla anche se l'opzione è attivata

  • L'origine non è raggiungibile. Un'unità scollegata, una condivisione non connessa o un server SSH non raggiungibile fanno sì che non venga eliminato nulla. È voluto.
  • Il tipo è File. L'opzione vale solo per Cartella e Albero di cartelle.
  • Carattere jolly o esclusione tolgono il file dalla sincronizzazione – allora non viene nemmeno eliminato.
  • Si tratta di una cartella. Vengono rispecchiati i file; una cartella eliminata nell'origine resta nella destinazione.

Non viene sincronizzato nulla

  • Il servizio in background è in esecuzione? Servizio e programma non sincronizzano contemporaneamente.
  • Se Avvia e Sincronizza una volta sono grigi, la configurazione non contiene alcuna sincronizzazione eseguibile – per esempio perché sono tutte inattive o mancano origine e destinazione.
  • La configurazione è stata salvata dopo l'ultima modifica?
  • Con origine o destinazione tramite SSH: l'altro capo risponde? AutoFileSync lo controlla prima di ogni esecuzione e salta la sincronizzazione finché il server non è raggiungibile o l'accesso non riesce. Il log riporta allora «Percorso SSH non raggiungibile» con il motivo.
  • Il server è di nuovo raggiungibile, ma non succede ancora nulla. Il risultato del controllo di raggiungibilità viene memorizzato, così non ogni esecuzione apre una nuova connessione. Dopo un tentativo fallito si ricontrolla al più presto dopo qualche secondo, con un guasto prolungato al massimo ogni cinque minuti. Possono quindi passare fino a cinque minuti prima che una connessione ripristinata venga notata.

Una connessione SSH non riesce

  • Errore di autenticazione – nome utente o password sono errati, oppure il server non consente l'accesso con password.
  • Errore di connessione – host o porta non sono raggiungibili.
  • La chiave host è cambiata – il server si presenta con una chiave diversa dalla prima volta. AutoFileSync allora si interrompe. Se il cambiamento si spiega, per esempio dopo una reinstallazione del server, la vecchia voce va rimossa dal file known_hosts del proprio profilo utente.
  • Account SSH non trovato – il nome prima dei due punti nel percorso non appartiene a nessuna connessione creata. Succede per esempio quando una connessione è stata rinominata; le sincronizzazioni interessate puntano allora ancora al vecchio nome.

In tutti questi casi la sincronizzazione interessata viene saltata per questa esecuzione: non si copia né si elimina nulla. Le altre sincronizzazioni continuano normalmente.

Compare un avviso per un'unità mancante – oppure no

Se un'origine o una destinazione non raggiungibile viene segnalata lo decide, per ogni sincronizzazione, l'opzione Avvisa se manca l'unità o la connessione SSH: attiva, dopo Sincronizza una volta c'è un avviso e una riga di avviso nel registro; disattivata, solo una riga informativa. Se una sincronizzazione avvisa e un'altra no, sebbene a entrambe manchi lo stesso disco, l'opzione è impostata diversamente. Tutto il resto in Unità e connessioni non raggiungibili.

Recuperare file eliminati

Se la modalità di eliminazione è impostata su Sposta nel cestino, i file si trovano nella cartella del cestino impostata, nella struttura del luogo di provenienza. Con Elimina definitivamente e con le destinazioni tramite SSH non esiste una copia di questo tipo.

Se un file di destinazione è stato sovrascritto, aiuta il Principio generazionale – purché fosse attivato prima: la versione precedente si trova allora accanto al file come .bak.1.

Sincronizzazione → Ripristina file… recupera entrambi senza dover cercare i file. L'elenco mostra i file eliminati dal cestino e le versioni precedenti, ciascuno con la cartella in cui torna: ciò che proviene da una destinazione viene messo nell'origine, così la sincronizzazione successiva non lo rimuove di nuovo. Un file esistente non viene mai sovrascritto; se il nome è già occupato, il file ripristinato riceve la data nel nome. Ripristina in… mette la selezione in una cartella a scelta. Le destinazioni tramite SSH e sul telefono non vengono esaminate.
