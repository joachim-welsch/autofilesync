Sincronizzare tramite SSH

Origine o destinazione possono trovarsi su un altro computer raggiungibile tramite SSH – per esempio un NAS, un server o un piccolo computer nella rete di casa. Sono possibili anche entrambi i lati contemporaneamente.

Creare una connessione

File → Nuova connessione SSH… oppure Modifica → Connessioni SSH… apre la gestione. Una connessione è composta da:

Nome Liberamente scelto. Con questo nome la connessione viene poi indicata nei percorsi.
Host Nome del computer o indirizzo IP.
Utente Account sul computer remoto.
Password Viene salvata cifrata nella configurazione, non in chiaro.

Nell'elenco le connessioni si possono creare, modificare, rinominare ed eliminare. Se una connessione viene rinominata, le sincronizzazioni che la usano si adeguano automaticamente.

Scrivere percorsi remoti

Un percorso remoto è composto dal nome della connessione, da due punti e dal percorso sul computer remoto:

nas:/home/anna/documenti

Nella finestra di una sincronizzazione, il pulsante SSH accanto a origine e destinazione porta prima alla scelta della connessione e poi a una finestra che sfoglia le cartelle del computer remoto – con dimensione e data di modifica, così il posto giusto si trova senza digitare.

Che cosa cambia

  • I collegamenti simbolici sul computer remoto non vengono seguiti. Vengono saltati, così un collegamento a una cartella superiore non crea un ciclo infinito.
  • L'eliminazione è definitiva. Il cestino è disponibile solo in locale; per spostarvi un file remoto bisognerebbe prima scaricarlo. Questo riguarda Elimina anche nella destinazione i file eliminati come Elimina l'origine dopo la copia, anche se quest'ultima per le origini remote non viene comunque eseguita.
  • Gli attributi dei file non vengono modificati sul lato remoto.
  • Se il server non è raggiungibile, AutoFileSync lo distingue da «lì non c'è più niente» e non tocca la destinazione. Un'interruzione della connessione non porta quindi a eliminazioni.
  • Alla prima connessione viene memorizzata la chiave del server. Se in seguito cambia, AutoFileSync interrompe la connessione e segnala il sospetto di un attacco man-in-the-middle.

Il controllo prima di ogni esecuzione

Prima che una sincronizzazione con un lato remoto inizi, AutoFileSync si assicura che l'altro capo ci sia: si connette, controlla la chiave del server ed effettua l'accesso. È la stessa domanda che per un percorso locale significa «l'unità è collegata?». Se uno di questi passaggi non riesce, la sincronizzazione viene saltata per questa esecuzione – non si copia né si elimina nulla.

Per origine e destinazione valgono criteri diversi:

  • L'origine deve esistere. Se il server risponde ma segnala «non esiste», l'origine è scomparsa – e una sincronizzazione la cui origine è scomparsa resta ferma invece di riprodurre la scomparsa. Altrimenti una cartella di origine eliminata, insieme a Elimina anche nella destinazione i file eliminati, svuoterebbe la destinazione.
  • Per la destinazione basta che la connessione riesca. Una cartella di destinazione che non esiste ancora viene creata da AutoFileSync stesso – non deve bloccare la sincronizzazione.

Il risultato viene memorizzato, così non ogni esecuzione apre una nuova connessione. Un lato remoto raggiungibile viene ricontrollato al massimo una volta all'ora, uno non raggiungibile al massimo ogni cinque minuti. Dopo un guasto possono quindi passare alcuni minuti prima che la sincronizzazione riparta da sola.
