Opzioni di una sincronizzazione

La scheda Opzioni nella finestra di una sincronizzazione stabilisce in base a che cosa vengono confrontate origine e destinazione e che cosa succede nei casi particolari.

Confronta i file per

Queste tre spunte decidono come AutoFileSync riconosce una differenza. Si possono combinare.

CriterioSignificato
Data Decide la data di modifica. È il caso più comune e di gran lunga il più veloce.
Dimensione Dimensioni diverse contano come differenza.
Contenuto I file vengono confrontati in base al contenuto. È preciso, ma richiede tempo per leggere entrambi i lati. Con la sincronizzazione bidirezionale è inoltre la data di modifica a decidere quale lato è il più recente – un semplice confronto del contenuto non può stabilirlo.
Tolleranza in secondi Due date di modifica che distano al massimo questi secondi contano come uguali. Il campo è attivo solo se il confronto per Data è attivato; il valore predefinito è 2 secondi, vedere Tolleranza e file system.

Tolleranza e file system

Durante la copia AutoFileSync riprende la data di modifica dell'origine, ma la destinazione la memorizza solo con la precisione consentita dal suo file system. Senza tolleranza, a ogni esecuzione l'origine risulterebbe più recente della propria copia di una frazione di secondo e verrebbe copiata di nuovo ogni volta. La tolleranza deve essere almeno pari al passo di tempo più grossolano tra i due lati:

File systemPrecisione della data di modificaTolleranza necessaria
ext4, Btrfs, XFS, APFSnanosecondi0 s
NTFS100 nanosecondi1 s
exFAT10 millisecondi1 s
HFS+, server SFTPsecondi interi1 s
FAT32, FAT16 (chiavette USB, schede di memoria)2 secondi2 s

Il valore predefinito di 2 secondi copre tutti questi casi. FAT inoltre memorizza l'ora come ora locale: dopo il passaggio tra ora legale e ora solare tutti i file risultano spostati di un'ora. Per evitarlo si può impostare per un po' la tolleranza a 3600 secondi oppure confrontare anche per Dimensione.

Il rovescio della medaglia: se un file viene salvato di nuovo entro la tolleranza dalla modifica precedente, e nel frattempo c'è stata un'esecuzione, la seconda modifica viene notata solo al salvataggio successivo. Chi modifica file in rapida successione fa bene ad attivare anche Dimensione oppure a impostare la tolleranza a 0, se entrambi i lati memorizzano l'ora con la stessa precisione.

Le opzioni nel dettaglio

OpzioneEffetto
Elimina l'origine dopo la copia Dopo una copia riuscita il file di origine viene rimosso – nel cestino o definitivamente, a seconda della modalità di eliminazione. La sincronizzazione diventa così uno spostamento. Per origini raggiunte tramite SSH l'opzione non ha effetto.
Sincronizzazione bidirezionale Conta anche la direzione opposta: ciò che esiste solo nella destinazione viene copiato nell'origine, e una destinazione più recente prevale su un'origine più vecchia. Insieme a Elimina anche nella destinazione i file eliminati prevale l'eliminazione – attivarle entrambe raramente ha senso.
Copia anche se il file di destinazione è più recente Normalmente AutoFileSync non sovrascrive un file di destinazione più recente dell'origine. Con questa opzione lo fa. Con la sincronizzazione bidirezionale attivata l'opzione è bloccata, perché lì non ha senso.
Principio generazionale Prima di sovrascrivere un file di destinazione esistente, AutoFileSync lo rinomina: relazione.doc diventa relazione.doc.bak.1, la volta successiva .bak.2 e così via. Le versioni precedenti vengono così conservate. Tenere presente che queste copie restano nella destinazione e occupano spazio – non vengono eliminate automaticamente.
Elimina anche nella destinazione i file eliminati Un file che esiste ormai solo nella destinazione viene eliminato lì – la destinazione diventa quindi uno specchio dell'origine. Dettagli e limiti sono nella sezione qui sotto.
Prova di backup Ogni esecuzione che ha copiato qualcosa o ha incontrato un errore scrive una voce in un file di prova; vedere Prova di backup.
Sincronizza file vuoti I file di dimensione 0 vengono normalmente saltati: un file vuoto è più spesso una scrittura interrotta che un file voluto vuoto, e copiarlo sopra un file di destinazione pieno significherebbe perdere dati. Con questa opzione vengono inclusi – pensata per segnaposto come .gitkeep e per file di blocco e di contrassegno. Attenzione: se il file di origine è vuoto e quello di destinazione no, la sincronizzazione sostituisce allora il contenuto della destinazione con il file vuoto.
Secondi di pausa Tempo di attesa tra due esecuzioni della sincronizzazione continua, regolabile da 1 a 60 secondi. Pause brevi notano prima le modifiche e caricano di più unità e rete.

Elimina anche nella destinazione i file eliminati

Questa opzione merita una descrizione più precisa, perché è l'unica che rimuove dati nella destinazione.

  • È disponibile per Cartella e Albero di cartelle, non per il tipo File.
  • L'eliminazione segue la modalità di eliminazione, quindi normalmente finisce nel cestino. Con una destinazione tramite SSH l'eliminazione è definitiva, perché un file remoto dovrebbe prima essere scaricato.
  • I file che comunque non appartengono a questa sincronizzazione, a causa del Carattere jolly o delle Esclusioni, restano intatti.
  • Se l'origine non è raggiungibile – unità scollegata, condivisione non connessa, server SSH non raggiungibile – non viene eliminato nulla. Un posto irraggiungibile non è un posto vuoto.
  • Vengono rispecchiati i file, non le cartelle: una cartella eliminata nell'origine resta nella destinazione con il suo contenuto.

Se l'opzione non ha effetto pur essendo attivata, è utile Quando qualcosa non va come previsto.
